## Context

当前系统已支持 chatbox 驱动分镜草案、多轮迭代、SSE 流式反馈与草案应用，但存在三个问题：
1. 左侧面板宽度偏窄，长上下文和 diff 可读性差。
2. 多轮对话中缺乏角色设定沉淀，导致镜头间角色形象不稳定。
3. 系统提示词偏“结构约束”，缺少“脚本导演”式交互引导，用户意图确认不充分。

## Goals / Non-Goals

**Goals:**
- 增强 chatbox 视觉宽度与信息承载能力，支持更长对话与分镜反馈。
- 引入“角色一致性约束层”，确保分镜中的人物形象在多轮迭代中保持统一。
- 引入“导演式系统提示词”与交互步骤，增强脚本质量和用户可控性。
- 在 SSE 过程中暴露更丰富事件（阶段、澄清、约束确认、草案摘要），提升透明度。

**Non-Goals:**
- 不引入完整角色素材库或外部角色资产管理系统。
- 不改动视频生成引擎（Seedance）和合成管线。
- 不在本次变更中实现多人协作或会话共享。

## Decisions

1. **新增 Character Profile 抽取与固化机制**
- 每轮生成前从历史对话和当前草案中抽取角色档案（姓名/外观特征/服饰/语气/禁止漂移项）。
- 将角色档案作为每轮 LLM 输入的硬约束拼接在 system/user prompt 中。
- 备选方案：仅靠用户文本上下文隐式保持一致。未采用，因稳定性不足。

2. **采用“脚本导演 + 分镜师”双角色系统提示词模板**
- 提示词分层：导演职责（剧情意图、节奏、冲突推进）+ 分镜职责（镜头语法、画面一致性、结构化输出）。
- 对话中允许澄清问题事件（如角色未定义、风格冲突、节奏不明确）。
- 备选方案：单一提示词模板。未采用，因难兼顾创意引导和结构稳定。

3. **扩展 SSE 事件协议**
- 保留 `progress/token/done/error`，新增可选 `clarification/constraint-summary` 事件。
- 前端按事件分区展示“正在思考”“已确认约束”“待用户确认问题”。
- 备选方案：仅输出 token。未采用，因交互可解释性不足。

4. **前端 chatbox 宽度可配置**
- 默认从 300 提升至 420（可通过常量或配置项控制），并优化消息区、摘要区、约束区布局。
- 备选方案：固定自适应百分比。未采用，因会挤压中间 flow 区域。

5. **对话消息采用追加式不可覆盖渲染**
- 用户消息、助手消息、阶段事件消息分离建模；阶段状态更新仅更新“状态消息”或追加事件，不覆盖历史对话正文。
- 生成结束后将状态消息收敛为结果摘要，但保留 token 过程记录（可折叠）。
- 备选方案：复用同一消息槽位做阶段替换。未采用，因会导致用户感知“对话丢失”。

## Risks / Trade-offs

- [角色档案抽取错误] → 在 UI 显示“当前角色约束摘要”，允许用户手动纠正后再继续生成。
- [导演式交互变长，增加轮次] → 引入“快速模式/精细模式”开关，默认快速模式仅关键澄清。
- [SSE 事件变多增加前端复杂度] → 统一事件 parser 与类型定义，未识别事件降级为日志文本。
- [更宽 chatbox 影响流程图可视空间] → 在窄屏下自动回退宽度并支持折叠。
- [消息持续追加导致列表变长] → 引入虚拟滚动或折叠历史分段，默认自动滚到底部。
