## Context

现有系统已支持 chatbox 对话分镜与角色一致性约束，但分镜仍以“直接对话生成”为入口，缺少前置的人物形象节点。导致用户在没有先明确角色设定时，分镜质量和角色稳定性受限。为提高视频可控性，需要将 workflow 升级为“先人物形象、后分镜生成”。

## Goals / Non-Goals

**Goals:**
- 在分镜编辑前提供人物形象节点，支持角色设定创建、确认、调整。
- 在 chatbox 中实现分阶段 workflow（形象生成→确认→分镜）。
- 分镜生成时强制携带角色形象元素，提升角色一致性和可控性。
- 保持与现有 SSE 机制兼容并增加形象阶段反馈。

**Non-Goals:**
- 不实现外部图片素材上传与视觉 embedding 管线。
- 不改动视频渲染/合成引擎。
- 不引入多人协作审批流程。

## Decisions

1. **引入 Character Node 作为流程入口节点**
- 在 FlowEditor 中新增人物形象节点，并将其置于 shot container 之前。
- 节点承载“角色名、外观关键词、服饰关键词、固定特征、禁改项”。
- 备选方案：仅在 chat 文本中隐式维护。未采用，因可视化弱、可编辑性差。

2. **Chatbox 采用阶段式状态机**
- 状态：`character_drafting -> character_confirmed -> storyboard_drafting -> storyboard_refining`。
- 在 `character_confirmed` 前，分镜生成入口按钮禁用或引导确认。
- 备选方案：单回合生成全部内容。未采用，因用户确认点不足。

3. **分镜输出强制注入形象元素**
- 后端在每轮 LLM 请求中注入 Character Node 配置；对输出做“角色元素覆盖度”检查。
- 若覆盖度不足，返回澄清或自动二次修正提示。
- 备选方案：仅依赖 prompt 软约束。未采用，稳定性不足。

4. **SSE 事件扩展人物阶段反馈**
- 增加 `character-draft`、`character-confirmation-needed`、`character-summary` 事件。
- 前端将其渲染为系统卡片，并保留历史对话不覆盖。
- 备选方案：复用 `progress` 文本。未采用，信息语义不清晰。

## Risks / Trade-offs

- [形象节点字段过多导致操作负担] → 提供最小必填字段与“自动提取建议”。
- [用户跳过确认直接生成分镜] → 前端 gating + 后端兜底校验，未确认则拒绝生成。
- [角色元素覆盖检测误判] → 先用关键词规则校验，并允许人工确认覆盖例外。
- [事件增多导致前端复杂度上升] → 统一事件类型与渲染层，未识别事件降级为日志。
